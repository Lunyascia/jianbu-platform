# 健步走系统 — 一步一步部署指南

> 这篇文档把整个系统部署拆成 **9 步**，按顺序往下做，**每步做完有"怎么检查对不对"**，通过后再进下一步。
> 出错时先看该步的提示，再查文末《附录 B：常见问题排查表》。

> 📌 **本文所有命令都是【命令提示符（CMD）】格式**（按 `Win + R` → 输入 `cmd` → 回车 打开）。
> 用 PowerShell 的话，把 `cd /d 路径` 改成 `cd 路径`、命令前的 `./` 改成 `.\` 即可（详见文末《附录 D》）。

## 部署前先看：系统要跑 4 样东西

```
┌─────────────────────────────────────────────────────────────┐
│  ① ② ③ ④ ⑤ ⑥ 是 6 个"东西"，要按顺序跑起来                    │
│                                                             │
│  ① Redis（缓存，底层）        命令启动，见第 1 步              │
│  ② MySQL（数据库，底层）      Windows 服务，一般已自启          │
│  ③ 后端（核心，一切接口在这）   java -jar 启动，见第 3 步        │
│  ④ 后台管理系统（管理员用）     pnpm dev 启动，见第 4 步         │
│  ⑤ H5 报名页（会员用）         python 静态服务，见第 5 步        │
│  ⑥ 小程序（会员用）            HBuilderX 运行，见第 6 步        │
└─────────────────────────────────────────────────────────────┘
        ① + ② 要先于 ③（后端启动时要连它们）
        ③ 要先于 ④⑤⑥（它们都调后端的接口）
```

**顺序总览：** 第 1 步 Redis → 第 2 步数据库 → 第 3 步后端 → 第 4 步后台 → 第 5 步 H5 → 第 6 步小程序 → 第 7 步手机联调 → 第 8 步正式上线。

## 第 1 步：启动 Redis

**为什么**：后端一启动就要连 Redis 存会话/榜单缓存，Redis 没起，后端会报错。

**操作**：打开一个 **CMD 窗口**，执行：
```cmd
cd /d E:\xmind\redis
redis-server.exe redis.windows.conf
```
窗口会打印 `Ready to accept connections`，然后**保持这个窗口开着不要关**。

> ⚠️ **为什么端口是 16379 而不是默认的 6379**：你电脑上 Windows 把 **6378–6477** 端口段列成了"系统排除端口"（Hyper-V/WSL 预留的），6379 被禁绑，Redis 会报 `Could not create server TCP listening socket ... bind`。所以已把 `redis.windows.conf` 里的端口改成 **16379**。**如果你自己装过 Redis，也要避开这段端口。**

**✅ 怎么检查**：另开一个 CMD 窗口执行
```cmd
cd /d E:\xmind\redis
redis-cli -p 16379 -a ruoyi123 ping
```
显示 `PONG` 就是成功了。（`-p 16379` 端口、`-a ruoyi123` 密码，都配置在 `redis.windows.conf` 里。）

> 小提示：这一步每次开机后都要做。嫌麻烦也可以把 Redis 装成 Windows 服务自动启动，需要时再问我。

## 第 2 步：初始化数据库（一次性，只在第一次部署时做）

```cmd

mysql --default-character-set=utf8mb4 -uroot -p123456 ry-vue < walking_award_config.sql
```

> ① 建 9 张业务表（会员/报名/步数/积分/奖励/证书/审计）
> ② 建后台菜单/角色/权限（健步走管理目录）
> ③ 工会组织树 + sys_dept 加会员总数列
> ④ 活动参数列 + 中奖名单菜单
> ⑤ **奖励管理**：walking_award 加列 + 奖励管理菜单 + 活动 1001 默认奖励档位

**✅ 怎么检查**：执行后输入
```cmd
mysql --default-character-set=utf8mb4 -uroot -p123456 ry-vue -e "SHOW TABLES LIKE 'walking_%';"
```
应该看到 **9 张表**：`walking_activity / member / registration / step_record / points / award / certificate / cheat_log / audit_log`。

> ⚠️ 这些脚本**只能执行一次**。重复执行 ③④ 会报"Duplicate column"错误，属正常，不影响使用。
> 报错了也**不要重跑**，直接进下一步。

## 第 3 步：启动后端（核心）

**为什么**：H5、小程序、后台全都调后端的接口，后端是"心脏"。

### 3.1 如果没有打包产物，先编译（改过后端代码才需要）

后端 jar 在 `E:\wechatdevProject\RuoYi-Vue-Plus-5.6.0\ruoyi-admin\target\ruoyi-admin.jar`。
如果这个文件存在且你**没改过后端代码**，跳过 3.1，直接到 3.2。
如果刚改了代码（比如加了接口），先编译：
```cmd
cd /d E:\wechatdevProject\RuoYi-Vue-Plus-5.6.0
mvn clean package -DskipTests -Pdev
```
> `-Pdev` 表示用开发环境配置（连接本机 MySQL `ry-vue`）。编译成功后 `target` 里会重新生成 `ruoyi-admin.jar`。

### 3.2 启动

```cmd
cd /d E:\wechatdevProject\RuoYi-Vue-Plus-5.6.0\ruoyi-admin\target
"C:\Users\27181\dev\jdk-17.0.20+8\bin\java" -jar ruoyi-admin.jar --spring.data.redis.port=16379 --spring.data.redis.password=ruoyi123 --api-decrypt.enabled=false
```
看到类似下面这行日志，表示启动成功，**这个窗口保持开着**：
```
Started DromaraApplication ...
Tomcat started on port 8080
```
> `--spring.data.redis.port=16379`：Redis 端口（本机 6379 被 Windows 排除，见第 1 步）
> `--spring.data.redis.password=ruoyi123`：Redis 密码（与第 1 步一致）
> `--api-decrypt.enabled=false`：开发期关闭接口加密，方便调试（生产再开启）
> `--captcha.enable=false`（可选）：开发期跳过后台登录验证码，方便联调；生产不要加
> 日志里出现 `snail-job ... ERROR` 属正常噪音，不影响运行，可忽略。

**✅ 怎么检查**：浏览器打开
```
http://localhost:8080/walking/activity/current
```
能看到一段 JSON（活动信息或 `{"code":...}`）就成功了。如果报错 404 说明后端没起来，回看上面的日志。

## 第 8 步：正式上线（真实活动，公网可访问）

> 本地演示够了可以直接跳过。正式活动需要：**一个已备案的 https 域名** + **把后端部署到服务器**。

### 8.1 准备域名和 HTTPS 证书

- 准备一个已备案域名，如 `walk.example.com`，配好 HTTPS 证书（阿里云/腾讯云可免费申请）。
- 这是**小程序正式版的硬性要求**：小程序只能请求已备案 https 域名，不能填 IP。

### 8.2 部署后端到服务器

1. 把 `ruoyi-admin.jar` 上传到服务器，用 `nohup java -jar ...` 后台运行（同样要 JDK 17 + Redis + MySQL）。
2. 服务器上 Nginx 反代 `/walking/**` 到本机 8080。参考配置：
```nginx
server {
    listen 443 ssl;
    server_name walk.example.com;
    ssl_certificate     /path/cert.pem;
    ssl_certificate_key /path/key.pem;
    location /walking/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```
3. 浏览器验证 `https://walk.example.com/walking/activity/current` 能返回 JSON。

### 8.3 配置微信小程序合法域名

微信公众平台（mp.weixin.qq.com）→ 开发管理 → 开发设置 → 服务器域名 → **request 合法域名** 填：
```
https://walk.example.com
```

### 8.4 切真实微信能力（上真号）

| 项 | 位置 | 操作 |
|---|---|---|
| 小程序 AppID | `jianbu-app/manifest.json` | 填写自己的 AppID，并确认与公众平台一致 |
| 后端 AppID/Secret | 后端 `application.yml` 的 `wx.appid` / `wx.secret` | 填真实值（AppSecret 别提交到 git） |
| 内容安全 | `wx.content-check.enabled` | 开发期 `false`（本地敏感词）；上线改 `true`（微信 msgSecCheck） |
| 接口加密 | 启动参数 `api-decrypt.enabled` | 生产建议 `true`，前后端需一致 |

### 8.5 小程序上传发布

1. HBuilderX → 发行 → 小程序-微信 → 填 AppID → 生成 `dist/build/mp-weixin`。
2. 微信开发者工具 → 导入 → 上传 → 填版本号/备注。
3. 微信公众平台 → 版本管理 → 提交审核 → 审核通过 → **发布**。

**✅ 上线后检查**：用手机微信搜小程序 → 报名 → 打卡 → 排名，全流程真机过一遍。

## 附录 B：常见问题排查表

| 现象 | 原因 | 解决 |
|---|---|---|
| Redis 报 `Could not create server TCP listening socket ... bind` | 端口 6379 在 Windows"排除端口段"(6378-6477) 里，被系统禁绑 | 已改用 16379（见第 1 步），不要改回 6379 |
| 后端启动报 Redis 连接失败 | Redis 没启动 / 端口没对上 | 做第 1 步；后端参数必须是 `--spring.data.redis.port=16379` |
| 后端启动报数据库连接失败 | MySQL 没启动 / 密码不对 | 确认 3306 在监听；账号 `root/123456` |
| 后端报 `Invalid bound statement` | 表没建 / 模块没打包进去 | 补第 2 步；`mvn clean package -Pdev` 重打 |
| 后台登录后没有健步走菜单 | 菜单脚本没执行 | 补执行第 2 步的 ② 和 ④ |
| 小程序请求报"域名不合法" | 没开本地校验 | 微信开发者工具 → 详情 → 本地设置 → 勾"不校验合法域名" |
| 小程序连不上后端 | 地址不对 / 后端没起 / 防火墙 | 核对 `request.js` 的 `BASE_URL`；后端窗口在不在；防火墙放行 8080 |
| 手机打不开报名页 | 防火墙 / 不在同一 Wi-Fi / IP 变了 | 手机浏览器直接访问后端地址测连通；重查 `ipconfig` |
| H5 单位下拉是空的 | 后端没起 / 组织脚本没执行 | 确认第 3 步成功；补执行 `walking_org.sql` |
| 绑定手机号提示"尚未报名" | 手机号与报名页填的不一致，或还没报名 | 先在 H5 报名，再进小程序输**同一个**手机号 |
| 步数同步失败 | 没授权微信运动 / 记录日期不在活动期 | 首页授权"微信运动"；确认活动时间区间 |
| 日志一堆 `snail-job ... ERROR` | SnailJob 调度中心没部署 | **可忽略**，不影响业务 |
