# 健步走 — 核心业务规则汇总（主文档）

> 本文件为全系统（H5 报名页 / 小程序 / 后台 / 后端）**最权威的规则总表**。
> 各细化规则见：`07-积分与排名规则`、`08-奖项与步数同步规则`。

## 一、打卡

| 规则 | 说明 |
|---|---|
| 步数来源 | 微信运动自动同步；**每日步数封顶 15000 步**，超量不计入统计 |
| 每日达标线 | **7000 步**；当日**登录小程序同步步数**才算有效达标 |
| 结算时间 | 每日 **0:00—23:59** 累计步数 |
| 数据同步 | 每次打开小程序**实时拉取**，自动过滤**报名前、活动前**的无效步数 |
| 历史补录 | 自动补录未同步日的步数；补录数据**不追溯报名前日期** |
| 断卡判定 | 当日未登录同步步数 → **直接中断**连续打卡 |
| 数据锁定 | 活动**缓冲期不计积分/排名**；活动结束**次日 0 点统一永久锁榜**，期间数据不锁定 |

## 二、报名

| 规则 | 说明 |
|---|---|
| 手机号限制 | 一个手机号只能有一条报名记录；**单个微信号仅绑定一个手机号** |
| 审核未通过 | 可**修改原记录重新提交**；敏感拦截**自动保存表单草稿**（无需重填） |
| 打卡起点 | 从**打卡开始之日**起计算；**报名前步数不追认** |
| 禁止修改 | 审核通过后**姓名、手机号不可修改**；管理员可后台调整**单位、收货地址** |
| 报名时效 | **活动截止日关闭报名**；**缓冲期禁止新增报名** |

## 三、与两端的关系

### H5 报名页（先报名）
- 需按"报名时效"展示：报名未开始 / 报名中 / 已截止（截止后表单禁用+提示）
- 审核未通过 → 草稿自动保存（localStorage 已实现），可修改原记录重新提交

### 小程序（后验证，仅已报名会员）
- 打卡规则全部由后端执行，小程序仅展示（步数/达标/连续天数/积分）
- 断卡判定、历史补录、数据锁定、15000 封顶、7000 达标线 → 后端实现

## 四、后端实现要点（阶段 1）
- 步数入库时：过滤报名前/活动前数据、封顶 15000、按日 upsert
- 每日达标判定：步数≥7000 且当日有同步记录
- 连续打卡：当日无同步记录即中断归零
- 历史补录：拉取全部未锁定历史，更新后锁定；不追溯报名前
- 锁榜：定时任务，活动结束次日 0 点；缓冲期数据只同步不计分
- 报名：手机号唯一约束；审核通过后锁姓名/手机号；管理员可调单位/收货地址
