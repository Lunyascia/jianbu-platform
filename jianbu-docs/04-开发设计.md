1. 配置 `ruoyi-modules/ruoyi-generator/src/main/resources/generator.yml`：

## 3. 微信小程序接入

### 3.1 登录（code2session）
- **有现成底座**：RuoYi 已内置 `grant_type=xcx` 策略（`ruoyi-admin/.../web/service/impl/XcxAuthStrategy.java`），用 `AuthWechatMiniProgramRequest` 调 code2Session 换 openid。
- 本系统会员不是后台 sys_user，**另建独立会员登录**：
  ```
  POST /walking/member/login {xcxCode}
  → WxService.code2Session(code) → {openid, unionid, session_key}
  → 查 walking_member 按 openid
  → 无则新建（needPhone=true）
  → sa-token: StpUtil.login(memberId, new SaLoginModel().setDevice("Xcx"))
  → 返回 LoginVo(accessToken, expireIn, memberId, needPhone)
  ```
- 会员会话 token 复用 sa-token（Header `Authorization`），与后台一致但登录类型区分。

### 3.2 微信步数同步
- 小程序端：`uni.login` 授权 `scope.werun` → `uni.getWeRunData()` 拿 `{encryptedData, iv}`
- 后端：用 `session_key` + AES 解密（`WxService.decryptWeRunData`）→ 得到当日步数 → 校验活动期/异常 → 写 walking_step_record → 按规则算积分写 walking_points
- **开发期（未注册 AppID）**：提供模拟接口 `POST /walking/step/sync` 支持传 `steps` 字段直接入库，前端可填模拟值；真号后切换真实解密。

### 3.3 文本内容安全
- 开发期：`SensitiveWordFilter`（本地敏感词库 + 正则）过滤报名姓名/备注/手机号备注等文本
- 真号后：`WxService.msgSecCheck(content)` 调微信 `security.msgSecCheck`（需 access_token 缓存，`WxService.getAccessToken()`）
- 配置开关 `wx.content-check.enabled`：false=本地过滤，true=微信接口

### 3.4 WxConfig 配置项（application.yml，预留真号）
```yaml
wx:
  appid: ""            # 小程序AppID(注册后填)
  secret: ""           # AppSecret
  grantType: xcx
  content-check:
    enabled: false     # 是否启用微信msgSecCheck
```

## 4. 异常（作弊）检测算法

提交步数后按以下规则判定 `abnormal_flag`，命中即标记并写审计日志：
1. **单日上限**：steps > 活动配置上限（默认 80000）→ 异常
2. **活动期外**：record_date 不在 [start_date, end_date] → 异常
3. **突增检测**：当日步数 > 该会员近 7 日均值 × 3 且差值 > 10000 → 异常
4. **来源校验**：source=2（人工）需管理员操作记录，小程序端不允许伪造 source=1 之外的值

管理员处理动作（walking_cheat_log.handle_type）：
- 1 标记异常（仅标记）
- 2 删除异常步数数据（批量，删除对应 step_record，可能连带撤销积分）
- 3 停用账号（member.status=1 + 报名 status=4）
- 4 取消报名（registration.status=3）

## 7. 关键业务逻辑要点

- **积分计算**：`积分 = 当日步数 ÷ 1000 × points_per_thousand_steps`（整除），写入积分流水，用唯一约束防重复打卡
- **审核锁字段**：报名 status=2 后，会员 is_verified=1，前端/接口禁止修改 real_name/phone（后端校验兜底）
- **排名**：`SUM(steps) WHERE abnormal_flag=0` 按活动分组，缓存 Redis 提升性能
- **证书**：活动结束后按名次生成 walking_certificate，证书图可由模板 + 姓名/名次合成（Html2Canvas 或后端图片合成）
