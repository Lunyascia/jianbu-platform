# 健步走小程序 — 设计文档

> 适用范围：`jianbu-app`（uni-app Vue3，编译微信小程序）
> 关联文档：需求 `01`｜业务规则 `00/07/08`｜接口 `03`｜开发 `04`
> 本文档约定小程序端的**设计原则、设计系统、信息架构、页面规格、交互与状态规范**，是前端实现与后续改版的依据。

---

## 1. 设计目标与原则

### 1.1 设计目标
- **让打卡零门槛**：打开即自动同步步数，打卡在 1 次点击内完成；已登录用户打开小程序即自动打卡。
- **让成就感可见**：今日步数 / 达标状态 / 连续打卡 / 累计积分 / 排名，第一屏即可感知。
- **与工会活动气质一致**：主视觉参考"藤县工会活动"小程序，红橙渐变主色 + 健康绿，庄重而不失活力。

### 1.2 设计原则
| 原则 | 落地说明 |
|---|---|
| **一切以数据说话** | 不装饰性堆砌，每个模块都承载一条业务数据（步数/达标/积分/名次） |
| **状态优先于样式** | 明确区分"已打卡 / 未打卡 / 达标 / 未达标 / 异常"，用色与图标传达，而非文字堆叠 |
| **后端为准、前端展示** | 积分/断卡/封顶/锁榜等规则全部后端执行，前端只负责如实呈现（见 `00`） |
| **弱网可用** | 首页各卡片独立加载，接口失败不阻塞整页；后端未就绪时展示占位而非白屏 |
| **操作可撤销/可引导** | 拒绝授权可重新引导开启；未报名给出明确指引路径 |

## 2. 设计系统

### 2.1 色彩（uni.scss 中已有变量，全局复用）

| Token | 色值 | 用途 |
|---|---|---|
| `$jbw-primary` | `#E8392C` | 主色·活力红：导航栏、Tab 选中、主按钮、数字高亮 |
| `$jbw-primary-dark` | `#C62A1F` | 主色按下态 |
| `$jbw-success` | `#3DB87C` | 健康绿：达标、已打卡、成功反馈 |
| `$jbw-warning` | `#F5A623` | 警示橙：未达标、待处理、引导提示 |
| `$jbw-text` | `#333333` | 主文字 |
| `$jbw-text-muted` | `#999999` | 次要文字（标签、说明、占位） |
| `$jbw-bg` | `#F5F6F8` | 页面底色 |
| `$jbw-card-bg` | `#ffffff` | 卡片底色 |
| `$jbw-radius` | `20rpx` | 卡片圆角基准 |

**渐变色**：主视觉统一使用 `linear-gradient(120deg, #E8392C → #F07830 → #F5A623)`（Banner、打卡大按钮、获奖横幅、个人中心头部）。

**语义色用法约定**：
- 红 = 主操作 + 品牌 + 排行前三
- 绿 = 达标 / 已打卡 / 成功
- 橙 = 未达标 / 提示 / 需要用户注意
- 严禁用红绿以外的第三色表达"达标/未达标"对立语义。

### 2.2 字体与字号（rpx）

| 场景 | 字号 | 字重 | 色 |
|---|---|---|---|
| 大数字（今日步数/积分/名次） | 80 / 44 rpx | bold | 主色 |
| 页面区块标题（section-title） | 30 rpx | bold | #333 |
| 正文 | 28 rpx | regular | #333 |
| 列表主信息（姓名/奖项） | 30–32 rpx | regular/bold | #333 |
| 次要信息（单位/时间/说明） | 22–26 rpx | regular | #666 / #999 |
| 说明性小字（封顶提示/脚注） | 20–22 rpx | regular | #999 |

### 2.3 间距、圆角、阴影

| 元素 | 规范 |
|---|---|
| 页面左右留白 | 24 rpx |
| 卡片间距 | 24 rpx（垂直） |
| 卡片内边距 | 30 rpx |
| 卡片圆角 | 20 rpx |
| 列表行圆角 / 标签圆角 | 12–16 rpx |
| 胶囊按钮/标签圆角 | 999 rpx |
| 卡片阴影 | `0 4rpx 16rpx rgba(0,0,0,.04)`（轻、近、柔） |
| 证书等强调卡片阴影 | `0 8rpx 24rpx rgba(0,0,0,.08)` |

### 2.4 组件规范

| 组件 | 视觉 | 交互 |
|---|---|---|
| **主按钮** | 红橙渐变、胶囊、白字、通栏 | 按压加深；loading 态显示"同步中…/保存中…" |
| **次级按钮** | `#F7F8FA` 底、`#666` 字、胶囊 | 用于"返回/稍后再说" |
| **胶囊切换** | 白底容器 + 选中项红底白字 | 三段切换（排名页） |
| **统计卡片** | 两列或四宫格，数字主色加粗、标签灰字 | 无点击，纯展示 |
| **信息行** | 左灰标签右黑值，下边框分隔 | 仅展示 |
| **表单输入** | `#F7F8FA` 底、12rpx 圆角、内边距 20rpx | 键盘类型按内容（手机号 number） |
| **标签 pill** | 如"全县工会会员"：半透明白底白字 | 展示 |
| **日历格** | 14.28% 宽，方形，按状态着色（见 4.1） | 展示 |

### 2.5 图标与图片
- 装饰类用 **emoji**（奖牌 🥇🥈🥉🎖、单位 🏅），避免引入图标库，保证跨端一致。
- 活动封面 `cover_url` 由后端下发，Banner 区为渐变色兜底。
- 头像为"姓名首字"圆形色块，不做微信头像授权（降低权限诉求）。

### 2.6 动效
- 过渡：页面级使用小程序默认转场，不加自定义动画。
- 反馈：操作成功用 `uni.showToast`（success）；失败用 `icon:none` + 文案。
- 强调：Banner / 大按钮仅用静态渐变，不跑循环动画（省电、克制）。


## 4. 页面规格（逐页）

> 标注"已实现"表示当前代码已按此落地；"规范/待补"表示需按本文档对齐或补充。状态细节见第 5 节。

### 4.1 首页 `index`（打卡主战场）

**布局自上而下**：

| 区块 | 内容 | 关键交互 / 状态 |
|---|---|---|
| ① 活动横幅 | 渐变底 + 活动名 + 日期 + "全县工会会员"标签 | 数据来自 `/activity/current`（公开接口）；后端未就绪显示兜底文案"健步走线上活动" |
| ② 活动信息卡 | 活动名称、活动时间 | 纯展示 |
| ③ 我的报名卡 | 姓名、所在单位；未报名显示红色提示"请先在报名页完成报名" | 未报名 → 触发登录引导 |
| ④ 步数打卡卡 | 见下方"打卡三态" | **核心交互区** |
| ⑤ 统计卡 | 累计打卡天数 / 当前总积分 + 注释"总积分 = 基础分 + 额外奖励分" | 纯展示 |
| ⑥ 打卡日历卡 | 当月日历 + 连续打卡天数 + 图例（达标/已打卡/今天/未打卡） | 格子按状态着色，未来日置灰 |

**打卡三态（区块④）**：

```
状态A 未授权   → 虚线框提示"尚未授权获取微信步数，点击开启" → openSetting
状态B 未同步   → 红橙渐变大按钮"开始打卡" → authorize(scope.werun) → getWeRunData → /step/sync
状态C 已同步   → 绿色"已打卡"标签 + 今日步数大数字 + "达标/未达标"状态行
```

- **自动打卡**：已授权且今日未同步 → `onShow` 自动调 `getWeRunData` + `/step/sync`，无需点击。
- **封顶提示**：卡片底部小字"单日有效步数封顶 15000 步，超出部分不计入统计"。
- **日历着色**：达标 `#E8F8F0` 绿、已打卡 `#FFF3EF` 橙红底、今天红边框、未来灰、未打卡 `#F7F8FA`。

### 4.2 排名页 `ranking`

| 区块 | 内容 | 说明 |
|---|---|---|
| ① 榜单切换 | 三段胶囊：当日排名 / 总排名 / 积分排名 | 默认"当日"；切换即重新请求 `/ranking/list?board=` |
| ② 更新提示 | "实时更新"（当日）/ "每日凌晨自动更新，非实时"（总/积分） | 与 `07-积分与排名规则` 一致 |
| ③ 榜单列表 | 名次圆点 + 姓名 + 单位 + 步数/积分 | 前三名名次圆点主色实底，其余灰底；值主色加粗 |
| ④ 空态 | "暂无数据" | 居中灰字 |
| ⑤ 榜单说明卡 | 粉底提示卡，解释更新机制与锁榜规则 | 文案固定，见 `08` 第 3 节 |

> **规范（待补）**：当前列表为 `name` 字符串直显；建议后端返回结构 `{rank, name, dept, value}`，前端按结构渲染，并为"我的名次"增加"我"高亮定位（置顶 + 红边标记）。

### 4.3 奖励页 `award`

| 区块 | 内容 | 展示条件 |
|---|---|---|
| ① 我的获奖横幅 | 渐变红底 + 获奖等级徽章 + "恭喜您获奖！" | **仅 `hasAward=true`** 显示 |
| ② 电子荣誉证书 | 金色边框证书：姓名 / 活动 / 等级 / 单位 / 日期 | 动态填充，`/award/mine` 下发 |
| ③ 收货地址 | 收货人 + 手机号 + 详细地址 + "保存地址" | 中奖用户填写，`/award/address` 保存 |
| ④ 个人奖项列表 | 4 档：一/二/三等奖、优秀奖（奖牌 emoji + 名额 + 奖品） | 静态展示 |
| ⑤ 集体奖项 | 先进组织单位（5 家）+ 评选说明 | 静态展示 |

**证书设计要点**：红金双色装饰条 + `#F0E0C0` 内框 + 金色"荣誉证书"标题 + 红色获奖等级。证书非图片合成，是纯视图层动态填充，便于后端改期/改名后即时生效。

### 4.4 我的页 `mine`

| 区块 | 内容 | 说明 |
|---|---|---|
| ① 信息头部 | 红橙渐变底 + 姓名首字圆形头像 + 姓名/单位/手机号 + 右上"登录/已登录" | 未登录显示"未登录/请先登录"，点击跳登录 |
| ② 报名信息明细 | 姓名 / 手机号 / 单位 / 报名状态 | 纯展示 |
| ③ 我的数据 | 四宫格：累计打卡天数 / 当前连续打卡 / 活动总步数 / 当前积分 | 数字主色加粗 |

### 4.5 登录页 `login`（三态页）

| 状态 | 界面 | 触发 / 说明 |
|---|---|---|
| `loading` | 居中"正在登录…" | 进入即 `uni.login` → `/member/login`（静默） |
| `phone` | 标题"关联手机号" + 手机号输入 + "绑定并登录" | 需绑定或当前手机号未匹配报名；手机号必须与报名一致 |
| `not-registered` | "尚未报名" + 三步指引 + "返回"按钮 | 手机号查无报名记录；提示先到 H5 报名页报名 |
| `error`（辅助） | 红底错误框显示具体报错 | 排查期保留，用于显示登录/绑定失败原因 |

**关键规则**：身份桥梁是**手机号**——小程序绑定手机号 = H5 报名手机号，匹配才放行（`05-部署文档` 2.5 节）。

## 5. 交互与状态规范

### 5.1 加载
- **首屏**：登录态 `loading` 页居中文字；首页各卡片独立 `try/catch` 加载，单卡失败不阻塞整页。
- **列表**：数据回来前保留容器高度（或直接空列表），不跳闪。
- **按钮**：请求中 `loading` 属性置灰并显示文案（"同步中…/绑定并登录/保存中…"）。

### 5.2 空态 / 无数据
- 榜单空 → "暂无数据"（居中、灰、加内边距）。
- 未中奖 → 奖励页顶部"我的获奖"整个隐藏，不显示空卡片。
- 日历空 → 正常渲染日历，无记录格子即为"未打卡"灰态。

### 5.3 错误与重试
- 网络失败 → `uni.showToast({ title: '网络错误，请确认后端已启动', icon: 'none' })`（request 层统一）。
- 登录失效/会话过期/会员不存在 → 清 token 并 `reLaunch` 登录页（request 层统一判断 `code===401` 或 msg 关键词）。
- 业务失败 → 展示后端 `msg`；不吞掉错误信息（登录页单独展示错误详情，便于联调排查）。

### 5.4 权限授权流程（微信运动）
```
进入首页 → checkStepAuth() 读取 scope.werun
  ├─ true  → granted → 若今日未同步则自动同步（免点击打卡）
  ├─ false → denied  → 显示"尚未授权"虚线框 → 点击 → openSetting → 用户开启 → 返回 granted
  └─ undefined → 未询问 → 显示"开始打卡"按钮 → 点击 → authorize → 授权/拒绝
```
- 拒绝授权不强制弹窗骚扰：以虚线引导框常驻，用户主动点击才调 `openSetting`。
- 真机需在微信中授权"微信运动"（见 `06-AppID注册指引` 第四节）。

### 5.5 步数同步闭环
```
打开小程序 → onShow
  ├─ 已授权 & 今日未同步 → getWeRunData → /step/sync（自动）
  └─ 未授权 → 打卡按钮 → authorize → getWeRunData → /step/sync
同步成功 → 更新 今日步数/达标/打卡天数/积分/连续天数 → toast"打卡成功"
```
> 规则边界（前端仅展示，后端执行）：单日封顶 15000；≥7000 且当日同步才算达标；断卡判定在后端；昨日步数需次日登录才同步进来。

### 5.6 登录闭环
```
打开任意 Tab → 无 token → navigateTo 登录页（3s 冷却）
登录页 → uni.login → /member/login
  ├─ needPhone=false & 已报名 → switchTab 首页
  ├─ needPhone=true            → 绑定手机号 → /member/phone
  │    ├─ 匹配报名 → 存 token → switchTab 首页
  │    └─ 无报名   → not-registered 指引页
  └─ 已绑号但未报名 → 提示换绑报名时的手机号
```

### 5.7 Toast / 反馈规范
- 成功：`icon:'success'`（"打卡成功 / 绑定成功 / 地址已保存"）。
- 失败/提示：`icon:'none'` + 具体文案。
- 表单校验失败：toast 说明具体原因（如"请输入 11 位、以 1 开头的手机号"），不做整表单红框报错。

## 6. 视觉实现基线（与代码对齐）

| 项 | 值 | 所在文件 |
|---|---|---|
| 导航栏 | 背景 `#E8392C`、白字 | `pages.json` globalStyle + 各页 style |
| TabBar | 4 项、选中 `#E8392C`、未选 `#999999` | `pages.json` tabBar |
| 主题变量 | 红/绿/橙/文字/底色 | `uni.scss` |

| 请求封装 | baseURL `/walking`、Authorization 头、统一错误处理 | `utils/request.js` |

**一致性检查点**（改版必查）：
1. 所有主色出现点应来自 `$jbw-*` 变量，禁止散落硬编码色值（渐变里的 `#F07830/#F5A623` 属固定品牌渐变，允许）。
2. 卡片统一 `24rpx` 外边距 + `30rpx` 内边距 + `20rpx` 圆角。
3. 状态语义色不可互换：绿=成功/达标，橙=未达标/警示，红=主操作/品牌。
4. 新页面必须纳入本架构图或显式声明为独立入口（本小程序无活动列表/报名页）。

## 7. 可用性与无障碍

- **点击目标**：主按钮高度 ≥ 80rpx，Tab 常驻，符合拇指热区。
- **文字对比**：正文 #333 on #fff、次要 #999 on #fff 均满足可读性；渐变底上文字一律白色。
- **弱网降级**：首页不因单个接口失败而白屏，均有兜底文案/占位。
- **防误触**：登录/绑定的成功跳转延迟 600ms，先 toast 再切换。
- **防循环跳转**：未登录/未报名引导跳转带 3s 冷却，避免两个页面互跳死循环。
